# 2026-04-21 Tue — Datacore Phase 1 Installation

## Summary

Completed Phase 1 of datacore setup for Hermes. Built the full `~/Data` scaffold with GTD system, layered context, Python utilities, and a Hermes-native skill.

## What Was Built

### Directory Structure
- `~/Data/` — Root datacore installation
- `.datacore/` — System core (agents, commands, lib, modules, registry, workflows, state)
- `0-personal/` — Personal space with org files and PKM
- `3-knowledge/` — Shared knowledge base (zettel, literature, pages, reference)

### Python Utilities
- `context_merge.py` — Layered context builder (DIP-0002). Merges `.base.md` → `.space.md` → `.local.md` into composed `.md`. Validates PUBLIC layers for private content.
- `date_utils.py` — Canonical date operations. Prevents LLM day-of-week hallucinations. Supports today, dow, validate, add, parse, org-stamp, fix.
- `org_parser.py` — Lightweight org-mode parser. count, list, add tasks. No dependency on full org_workspace.

### GTD Org Files
- `inbox.org` — Single capture point (sacred, always return to zero)
- `next_actions.org` — Active tasks with `:AI:` tags for delegation
- `someday.org` — Someday/maybe and reading lists

### Workflows (YAML)
- `today.yaml` — Morning briefing: sync, nightshift results, briefing generation
- `wrap-up.yaml` — Session close: task review, journal, learning extraction, engram ingestion, inbox check
- `continue.yaml` — Resume work: continuation tasks, stale check, next action suggestion

### Registries
- `agents.yaml` — inbox-processor, daily-briefing-generator, session-learning, knowledge-extractor, structural-integrity, module-registrar
- `commands.yaml` — /today, /wrap-up, /continue, /tomorrow, /ingest, /research

### Hermes Skill
- `~/.hermes/skills/datacore/SKILL.md` — Auto-triggers on today, wrap up, continue, tomorrow, process inbox, add task, agenda, weekly review, zettel, journal
